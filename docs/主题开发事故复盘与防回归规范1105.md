# 主题开发事故复盘与防回归规范

日期：2026-11-05。适用于译见 Pro 新增主题、独立页面重绘，以及现有主题的绑定、模板、缓存和生命周期调整。

## 结论

这次属于本应在主题改造时避免的基础性集成错误，不是字体、纸纹或 Avalonia 绘制能力的问题。

- 听析标签失效：新旧主题共享业务 VM，隐藏旧页面的双向绑定仍能反向修改状态，把长卷刚选择的标签改回“总结”。
- 实时正文丢帧：长卷新增的结果保护，把浮动字幕的刷新代次错误地当成正文会话的有效性条件，导致特定时序下正常识别事件被丢弃。
- 验收缺口：此前覆盖了外观、布局及部分隔离业务，却没有覆盖触发故障的新旧页面共存和异步刷新组合。通过的检查不能证明未覆盖的路径正常。

补丁本身不复杂：七处绑定方向明确化，再将正文与浮窗的代次分离。定位耗时的原因，是最初没有优先利用“其他主题正常”这个对照，也没有尽早还原真实主窗的缓存关系。

实现和验收没有守住边界，是本次开发应承担的问题，不能用“用户配置复杂”或“框架比较特殊”解释过去。

**主题可以有独立控件树和布局，但不应因此产生另一套业务事实。**

## 主题与业务的正确关系

本项目允许长卷、原稿书斋和经典主题使用不同页面结构。独立重绘不是错误，也不应退回给旧页面套背景。

| 对象 | 应有归属 | 主题能够做什么 |
| --- | --- | --- |
| 字体、纸面、分栏、书脊、局部字号、阅读滚动位置 | 呈现层 | 独立设计与保存必要的呈现状态 |
| 当前音频、转录段落、任务、聊天会话、配置 | 共享业务层 | 显示同一对象，通过明确操作修改 |
| 识别服务、启停、重连、取消、结果接收资格 | 共享业务协调层 | 调用既有业务能力，展示其状态 |
| 浮窗排版、浮窗缓存及其失效代次 | 对应浮窗呈现 | 刷新自身，不能据此判定业务正文失效 |
| 业务 VM／服务的最终释放 | 明确的唯一所有者 | 换主题解除自身订阅，不重复释放共享业务 |

“共享 VM”不自动等于“业务隔离正确”。两棵控件树绑定同一个 VM 后，任何一棵树的双向绑定、选择回调、自动回退或默认值同步，都可能成为业务写入者。

## 听析标签为什么点击后没有效果

### 用户看到的现象

文件和总结已经加载，点击“转录／导图／播客”后正文仍停在总结。状态文字甚至显示“转录段落已刷新”。

“段落已刷新”表明切换事件曾进入业务层，不能据此认定当前仍选中转录，也不能只检查按钮有没有 Click。

### 实际发生的顺序

- 主窗保留经典 `AudioLabView` 和长卷 `SongScrollAudioLabView` 两份页面缓存。
- 两页绑定同一个 `AudioLabViewModel`；旧页只是隐藏，没有解绑。
- 点击长卷“转录”，原 Click 处理正确地将 `SelectedTab` 改为 `Transcript`，并刷新段落。
- 隐藏旧页的 RadioButton 比较绑定参与反向写入，又把共享 `SelectedTab` 写回 `Summary`。
- 长卷正文按最终 VM 值显示总结，于是出现“按钮点过、状态更新过、正文却没切换”的表象。

失败报告中的实际变化为 `Transcript → Summary`、`MindMap → Summary`、`Podcast → Summary`。文件加载始终只有一次，未发生后续重选或递归加载，因此此次不能归因为文件加载重置标签。

### 为什么只看经典主题容易漏掉

经典页面自身被点击时，后续 Click 可以再次把目标标签设回来，最终正文看起来正常。失败报告中，经典点击也曾出现 `Summary → MindMap` 这样的多余中间变化。

因此准确结论是：旧绑定的隐患在多呈现共享状态后变成了长卷的可见故障，而不是“经典的所有绑定都正确，新主题按钮没接好”。

### 框架机制与修复

Avalonia 11.3.11 的 `ToggleButton.IsChecked` 默认绑定模式为 TwoWay，RadioButton 继承该属性。`ObjectConverters.Equal` 是正向比较转换器，没有提供反向转换委托；不能把“是否选中某个枚举值”当成可直接反向编辑枚举的属性。

当前修复位于 `Views/AudioLabView.axaml`：七个内置标签的比较绑定显式使用 `Mode=OneWay`。标签选择仍由原有 Click／`SetTab` 写入，未增加第二份标签状态或另一个业务 VM。

这不是要求所有绑定改为 OneWay。文本输入、真实布尔设置等明确可编辑值可以使用 TwoWay；关键是区分**可编辑源值**和**由源值推导出的显示状态**。

## 实时正文为什么会被主题额外过滤

### 差异不只是画面，而是开始入口

经典开始入口关闭 `_songScrollFrameGuard`；长卷开始入口开启该守卫，原意是防止停止、取消后的迟到结果回填。

问题是旧实现把 `_floatingSubtitleEpoch` 也用于正文整帧拒收。该字段本来描述浮动字幕会话，重连或配置刷新路径中的 `ResetFloatingSubtitleSession` 都可能推进它。

具体触发窗口如下：

- 当前识别服务发布 partial 或 final，回调记录浮窗代次，并把处理投递到 UI 队列。
- UI 消费该事件之前，执行浮窗重置，浮窗代次发生变化。
- 长卷守卫发现代次不同，直接返回。
- 原文、译文、历史及 `LatestRealtimeFrame` 都没有更新，尽管事件仍来自当前服务。

同一组输入经经典开始入口能够显示，经长卷开始入口则被拒绝。这是新增主题协调代码改变业务接收语义，不是单纯的颜色或布局修改。

守卫状态由开始入口决定。已经从长卷启动后，仅切换外观不等于立即切换守卫语义；排查时必须记录启动顺序，而不能只记录截图时的主题。

### 当前修复的边界

| 事件 | 长卷正文的处理 | 浮动字幕的处理 |
| --- | --- | --- |
| 正常 partial／final | 当前服务、当前正文代次的 partial 更新正文，final 写入历史并发布终稿快照 | 继续遵守浮窗自身代次与句身份规则 |
| 单独重置浮窗 | 不使正常正文事件失效 | 清理浮窗缓存、推进浮窗代次 |
| 清空历史 | 推进正文代次，拒绝清空前已经排队的正文事件 | 同时清理浮窗 |
| 停止或连接取消 | 使用忽略标志拦截迟到结果 | 保留原停止与收尾行为 |
| 长卷重新开始 | 推进正文代次，隔离上一轮已排队事件 | 初始化新的浮窗会话 |
| 服务对象已更换 | 保留当前服务身份校验 | 保留对应服务与句身份校验 |

修复位于 `MainWindowViewModel.SongScroll.cs` 与 `MainWindowViewModel.TranslationAndUi.cs`。新增 `_songScrollFrameEpoch`，长卷开始和清空历史推进正文代次；浮窗重置不再决定正文是否有效。

修复不是删除所有保护，也不是保证同一个服务对象未来发出的任意旧数据都能被识别。已验证的是停止、清空和跨重新开始时的旧排队事件隔离，以及当前会话正常事件的接收。

### 对现场现象能够下什么结论

已证明：这处缺陷能在特定队列时序下造成经典与长卷的正文差异，修复后的同输入 A/B 已通过。

尚不能证明：现场整个会话持续无字的所有原因都只有这一处。单次重置会误丢跨越该次重置的排队事件，不代表重置之后所有新事件永远不能显示。

此前只读检查发现现场会话有六对原文／译文记录。这说明至少已有部分服务端结果写入文件，不能以最后几帧静音推断整段都未采集；但文件计数也不能证明每条结果都通过了 VM 门禁并进入可见控件。

因此，应分别报告“主题层丢帧缺陷已修”和“真实麦克风／云端识别是否复验通过”，不能把两者合并成未经验证的恢复结论。

## 为什么前面的验证没有发现

| 已做检查 | 能说明什么 | 漏掉了什么 |
| --- | --- | --- |
| 构建、XAML 诊断 | 代码与标记能够编译 | 绑定运行时回写及事件先后关系 |
| 截图、尺寸、字体、控件可见性 | 指定状态下呈现正确 | 用户操作能否到达并保持正确业务状态 |
| 固定假数据的听析外观检查 | 总结或播放器能够显示 | SelectedTab 根本不会变化，无法检验切页 |
| 单个长卷页面加真实 VM | 单页事件和绑定可以工作 | 隐藏经典页的反向写入者不存在 |
| 普通识别事件注入 | 服务事件能够走到文字呈现 | 没有制造事件排队与浮窗重置交错的窗口 |
| 工坊共享业务专项 | 工坊的会话、草稿等保持同源 | 不能替代听析或实时翻译的业务验证 |

最大的失误不是测试数量少，而是用不包含故障条件的通过结果回答了更大的问题。增加同类截图或更多固定假数据，不会补上这个缺口。

## 后续主题开发必须遵守的边界

### 呈现可独立，业务写入必须明确

- 可以重新组织页面、独立命名字体和样式，不强迫使用旧控件树。
- 标签选中、图标启用、模式比较、状态摘要等推导值，显式声明读取方向。
- 用户选择通过命令、事件或具有明确反向语义的属性进入业务层，同一个操作不同时由比较绑定和 Click 重复提交。
- 绑定前检查属性默认模式，不依赖“省略 Mode 应该是只读”的印象。
- 换主题不得重选模型、音源或文件，不得把空选择或模板默认值写回用户配置。

### 隐藏页面仍须视为活对象

- `IsVisible=false` 不等于解绑、卸载或停止订阅。缓存页仍可能接收属性通知、执行 setter 和调度回调。
- 排查写入来源时，要同时检查当前页面与隐藏缓存页，而不是只查看屏幕上的树。
- 自动选择、默认回退、焦点、热键等主动呈现行为，只应由有资格的当前呈现执行；真正的业务不变量由共享业务层维护。
- 主题页只解除自己的 UI 订阅，不在换页时 Dispose 共享业务 VM 或停止共享服务。

### 异步失效依据必须属于对应业务

- 使用代次或取消标记前，写清它代表什么、由哪些事件推进、允许丢弃哪些结果。
- 浮窗排版刷新、字体变化、页面重新挂载，不应自动等价为“识别正文已经过期”。
- 清空历史、停止、重启和更换服务的规则应分别设计，既不回填旧结果，也不误丢当前结果。
- 新主题需要“正在连接／取消连接”等交互时，应增强共享协调能力，不能在主题入口悄悄增加另一套结果接收标准。

### 样式与交互一起审查

- 纯配色不应调用业务 setter；模板修改要检查默认值、命中、焦点、禁用态和绑定方向。
- 弹层要明确自身字体、样式作用域和坐标单位，不能假定它与书册内部处于同一个缩放根。
- 字体和局部阅读字号归呈现层，不通过全局覆盖或修改用户业务字号来“统一外观”。
- 新派生 XAML 的生成字段隐藏、NameScope 查找、透明遮罩等是审查点，不是看见警告就认定的故障根因。必须用真实事件和状态轨迹确认。

## 最小充分验收要求

按实际改动选择检查，不要求每次改颜色都运行全量业务或真实云语音。

| 改动类型 | 最少要验证的行为 |
| --- | --- |
| 纸纹、颜色、字体、间距 | 受影响状态的可读性、布局、悬停／选中／禁用表现及旧主题恢复 |
| 按钮模板、绑定、模式切换 | 真实控件操作 → 目标业务值 → 稳定后的值 → 实际正文；不能只看 Click 回执 |
| 新控件树、共享 VM、页面缓存 | 真实主窗创建新旧缓存；加载非空内容；新旧主题往返；检查双方写入与对象身份 |
| 启停、取消、结果守卫 | 同服务同事件 A/B；正常 partial／final；停止、清空和重新开始时的排队事件；业务结果进入实际文字节点 |
| 识别资源、音频路由或协议 | 除上述 UI 检查外，按改动范围补实际音频／厂商链路验证，并单独说明结果 |
| 仅文档 | 校对事实、路径与链接；不构建、不启动应用、不追加功能测试 |

对于独立主题页，缓存检查至少覆盖“先旧后新再返回”和“先新后旧再返回”。不能用每轮只新建一个孤立窗口的测试替代这两种创建顺序。

一次操作应得到一次明确的业务状态迁移。除最终状态正确外，也要发现 `目标 → 默认值 → 目标` 这样的多余回写，避免它重复触发文件加载、生成或持久化。

受控事件能定位 UI 接线和守卫错误，不等于真实识别验收。准备宣称“真实录制和识别已恢复”时，仍须用已知内容的实际语音走完整链路；未完成时写明缺口，不扩大通过结论。

## 再次出现主题差异时的排查顺序

- 保持业务配置不变，用同一文件、同一服务输入和同一操作比较正常主题与异常主题；先记录页面创建和启动顺序。
- 标签问题检查“命中 → Click → VM 变化 → 后续反向写入 → 正文有效可见性”。给状态的所有写入口看调用栈，不只检查 Click 方法。
- 无字问题检查“服务发布事件 → VM 收到 → UI 队列消费／拒绝 → 快照 → 呈现集合 → 实际文字”。定位最后一个正确环节，再向后查。
- 短时记录必要计数和拒收原因，例如会话代次不符、服务不符、已停止；不要把原文、译文、密钥或完整配置写进诊断输出。
- 抓取回写栈只用于限定的诊断过程，不常驻高频音频帧日志。
- 同时核对源码、产物摘要和实际运行路径，避免用旧发布目录验证新 Debug 补丁。
- 输入桌面或前台命中检查失败时，保留失败并区分环境阻塞，不能直接改成合成点击后宣称原生交互通过。

后续改进不意味着为一次纯视觉改动立即重构所有页面或增加大量测试。应在触及相应风险时处理，并保持共享业务能力、主题独立设计和克制定向验证同时成立。

## 框架依据

- [Avalonia 11.3.11 ToggleButton](https://raw.githubusercontent.com/AvaloniaUI/Avalonia/11.3.11/src/Avalonia.Controls/Primitives/ToggleButton.cs)：`IsChecked` 默认 TwoWay，省略 Mode 不是只读保证。
- [ObjectConverters](https://raw.githubusercontent.com/AvaloniaUI/Avalonia/11.3.11/src/Avalonia.Base/Data/Converters/ObjectConverters.cs)：`Equal` 用正向函数产生比较结果。
- [FuncValueConverter](https://raw.githubusercontent.com/AvaloniaUI/Avalonia/11.3.11/src/Avalonia.Base/Data/Converters/FuncValueConverter.cs)：未提供反向委托时 `ConvertBack` 抛出 `NotImplementedException`，不能把单向比较直接当成双向编辑契约。

本次教训不是“主题不能重做”，而是：独立呈现必须保持业务语义一致，验证必须包含真正改变了的运行关系。
